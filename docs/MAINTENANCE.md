# Проверки и сопровождение

Структура модулей и их границы — в [ARCHITECTURE.md](ARCHITECTURE.md),
сборка и запуск доступны через [README](../README.md).

## Проверка изменения

```powershell
.\scripts\build.ps1 -Configuration Debug -Test
.\scripts\build.ps1 -Configuration Release -Test -Package
```

`tests/CoreTests.cpp` только запускает тематические наборы `tests/*Tests.cpp`.
Регрессии добавляются в соответствующий набор; общие фикстуры — в `TestSupport.hpp`.
CTest также проверяет синхронизацию ассетов с удалением старых файлов, загрузку
из чужой рабочей папки, снимки, ввод игры/Forge и перенос в Unicode-каталог.
Оконные сценарии находятся в `src/game/*Smoke.cpp` и `src/forge/ForgeSmoke.cpp`.

Для повторения только упавшей проверки используйте
`ctest --preset debug -R "имя_теста" --output-on-failure`.
Не запускайте оконные тесты двух конфигураций одновременно. Компиляция под нагрузкой
может исчерпать их лимиты времени; диагностируйте причину таймаута, а не повышайте лимит
без измерения. Результаты и снимки находятся под `out/build/windows-x64/`.

## Производительность

`scripts/build.ps1 -Configuration Release -Benchmark` запускает отдельный benchmark
и сохраняет `out/build/windows-x64/performance-Release.txt`. Он не входит в CTest.
Нагрузки и параметры определены в `tests/Performance.cpp`; `--combat-only` оставляет
боевые сценарии, `--presentation-only` — CPU-обновление маски тумана и перебор земли
в пределах камеры. Последний не измеряет время отрисовки Direct2D. Сравнивайте одну
конфигурацию и одинаковую нагрузку, с прогревом и повторениями. Отчёт должен содержать
времена и условия замера, не вывод о FPS.

## Поддержание документации

- Документируйте текущие контракты, ограничения и действия пользователя.
- Держите одно описание правила; из других руководств ставьте ссылку.
- Баланс, размеры, списки ассетов и схемы берите из каталогов/загрузчика.
- История экспериментов, одноразовые отчёты, снимки и старые замеры не дописываются
  к инструкциям: изменения остаются в Git, временные результаты — в `out/`.
- Завершённые задачи убираются из `TODO.md`; устойчивое правило переносится в профильный документ.
- При замене ассета сохраняются сведения об авторстве, лицензии и контрольной сумме.
