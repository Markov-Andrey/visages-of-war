# Данные игры

Это каталог **определений**, а не сохранение партии. В нём находятся характеристики типов,
имена, описания и связи. Положение, текущее здоровье, опыт и очередь приказов хранятся
в экземплярах симуляции и не записываются обратно в каталог.

## Где редактировать

| Файл относительно `assets/data` | Содержимое                                                              |
|---------------------------------|-------------------------------------------------------------------------|
| `catalog.json`                  | Версия, расы, список `entityFiles`, пути к командирам и правилам        |
| `entities/humans.json`          | Все определения людей: рабочий, Миротворец, летун, лучник, катапульта, герой, здания |
| `commanders.json`               | Командиры, раса, стартовые рабочий и герой, оформление точки сбора      |
| `abilities.json`              | Активные способности: числовой ID, название, стоимость маны и откат |
| `rules.json`                    | Общие правила получения опыта и пороги уровней                          |

Редактируйте исходные файлы в репозитории, затем запускайте сборку: она копирует данные
рядом с exe даже без изменений C++. Для быстрого эксперимента можно править `assets/data`
рядом с запускаемым exe; следующая сборка перезапишет такую копию. После правок перезапустите
игру: каталог загружается при запуске. В Forge клавиша F5 перечитывает каталоги и изображения.
Формат — обычный UTF-8 JSON, без комментариев и завершающих запятых.

## Оформление точки сбора командира

Необязательное поле `rallySprite` в записи командира задаёт анимированную точку сбора.
Без него или при `null` остаётся обычный флажок. Настройка относится к конкретному
командиру, а не ко всем представителям его расы. Сейчас она задана только у Валери.

Обязательны `image`, `scale` (0.01–4), `ticksPerFrame` (1–3600) и `frames` (1–128 кадров).
Каждый кадр содержит `source: [x,y,w,h]` и `anchor: [x,y]` — точку опоры **в пикселях
внутри этого кадра**, а не долю его размера. Все кадры рисуются с одним `scale`,
поэтому разная ширина прямоугольников не растягивает изображение.
Порядок массива задаёт цикл анимации; она использует тики симуляции и замирает на паузе.

Необязательное `teamMask` — PNG того же размера, что весь атлас `image`, либо `null`.
Для основы и маски используются одни координаты кадров. Поддерживается белый рисунок
на прозрачном фоне, включая полупрозрачные переходы, как у зданий.
Пути, размеры, границы кадров и положение опоры проверяются при загрузке.

Необязательное `light` задаёт небольшой ночной источник: `offset: [x,y]` — смещение
от точки опоры в пикселях исходника, `radius` — радиус в клетках (0.1–16),
`intensity` — сила (0–1), `color` — RGB (0–255). Без поля или при `null` света нет.
У Валери радиус 1.2 клетки, сила 0.7 и тёплый золотистый оттенок. Свет появляется
только вместе с собственной выбранной точкой, причём её клетка должна быть видима.
Днём свечение гаснет; оно не раскрывает туман войны и не добавляет обзор.

Маркер и соединительная линия показываются только владельцу выбранного, живого,
завершённого производящего здания, если клетка сбора разведана. Чужие и нейтральные
точки не отображаются даже при выборе здания. Это графическое обозначение приказа:
оно не занимает клетки, не даёт обзор, не выбирается и не попадает в Либрарий.

## Одна структура для всех сущностей

Необязательное булево поле `canDecompose` (по умолчанию `true`) управляет останками
мобильной сущности. Сейчас оно включено у всех юнитов, кроме героя. При `true` после
смерти остаётся принадлежащее игроку тело на 60 секунд, затем нейтральные кости на
300 секунд с момента создания. Двухсекундное проявление костей совпадает с исчезновением тела;
кости в конце также исчезают за две секунды через прозрачность. При `false` остаётся
только короткая анимация исчезновения, без постоянного тела и костей. Признак независим
от класса героя, типа движения и конкретного ID юнита.

В каждом файле сущностей находится объект `{"version": 1, "entities": [...]}`.
Все записи используют одинаковые поля. Пример героя:

```json
{
  "id": "human.hero",
  "canDecompose": false,
  "factionId": "humans",
  "name": "Рыцарь",
  "description": "Герой ближнего боя. Получает опыт за победы своей армии поблизости.",
  "cost": { "crystals": 0, "supply": 5 },
  "stats": {
    "health": 600, "mana": 200, "damage": 24,
    "level": 1, "dayVision": 10, "nightVision": 8
  },
  "mobility": {
    "enabled": true, "type": "walking", "speed": 3.2, "formationPriority": 1, "collisionRadius": 0.4
  },
  "worker": { "builder": false, "carryCapacity": 0 },
  "construction": { "enabled": false, "ticks": 180, "footprint": [1, 1] },
  "production": { "trainingTicks": 300, "trains": [] },
  "depot": false,
  "hero": { "healthPerLevel": 60, "damagePerLevel": 4 },
  "visual": "unit",
  "alternateForms": [],
  "attack": {
    "range": 1.5, "windupTicks": 6, "recoveryTicks": 6, "cooldownTicks": 18,
    "targets": "same_layer", "projectile": null
  },
  "sprite": {
    "image": "sprites/worker.png", "frameSize": [32,32], "size": [80,80],
    "anchor": [0.5,0.7125], "rows": [0,1,2,3,4,5,6,7], "idle": 0,
    "walk": [0,2,1,3], "windup": [4,5], "recovery": [6,7], "teamMask": "blue"
  }
}
```

| Поле                           | Значение                                                                                                 |
|--------------------------------|----------------------------------------------------------------------------------------------------------|
| `id`                           | Стабильный уникальный ID во всём каталоге; ссылки используют его, а не имя или номер строки              |
| `factionId`                    | Ссылка на расу из `catalog.json`, например `humans`; несколько командиров могут использовать её сущности |
| `name`, `description`          | Название и описание для игрового интерфейса и Либрария                                                   |
| `library`                      | Необязательный `true`/`false`, по умолчанию `false`: показывать запись в энциклопедии                    |
| `cost.crystals`, `cost.supply` | Цена получения и занимаемый лимит армии; оба целые и неотрицательные, лимит 0–100                        |
| `stats`                        | Базовые здоровье, урон, статичный уровень, радиусы обзора                                                |
| `mobility`                     | Доступность движения, тип, клетки в секунду, приоритет рядов строя от 1                                  |
| `worker`                       | Возможность строить и вместимость переносимых кристаллов; нули отключают рабочие функции                 |
| `construction`                 | Доступность строительства этой сущности, время в тиках и прямоугольный след `[ширина, высота]`           |
| `production.trainingTicks`     | Сколько времени нужно для обучения **этой** сущности                                                     |
| `production.trains`            | Массив ID производимых юнитов (до трёх); пустой массив отключает производство                            |
| `depot`                        | Принимает ли готовая постройка доставленные кристаллы                                                    |
| `hero`                         | `null` для обычного типа; объект с приростами характеристик включает развитие героя                      |
| `visual`                       | Временный вариант графики: `unit`, `hall`, `barracks`, `tower`                                           |
| `alternateForms`               | ID других форм; пустой массив, если форм нет                                                             |
| `attack`                       | Дальность, подготовка, завершение, перезарядка, допустимые цели и необязательный снаряд                  |
| `sprite`                       | Атлас юнита, направления, кадры фаз, размеры и командная окраска; для неподвижных зданий `null`          |
| `buildingSprite`               | Необязательные стадии постройки: масштаб, пороги прогресса, PNG, отдельные командные маски и привязки    |

Подробные таблицы всех параметров оружия и анимации: [Атаки и снаряды](COMBAT.md).
Необязательный `sprite.portrait` — путь отдельного PNG относительно `assets` для большого
портрета выбранного юнита / активной группы. Без поля или с `null` используется иконка Stand.
`sprite.icon` независимо задаёт PNG для кнопок. Необязательные `portraitMask` и `iconMask`
задают белые маски команды того же размера, что соответствующий PNG; маска без картинки запрещена.
Кадры в `directionRecipe` и общая смерть `sprite.death` поддерживают необязательный `teamMask`.
Подготовка графики: [UNIT_SPRITES.md](UNIT_SPRITES.md).
Стадии ратуши и подготовка масок в Photoshop: [Графика зданий](ASSETS.md#спрайты-ратуши-и-командная-маска).
Маски зданий применяют режим `Color` («Цветность»): белая область получает оттенок
команды с сохранением светлоты оригинала; чёрная остаётся неизменной.

В `buildingSprite.stages` требуется от 2 до 101 стадии со строго возрастающими `from`
от 0 до 100 включительно; крайние пороги обязательны. `teamMask: null` отключает маску
для этой стадии. Без `buildingSprite` или при `null` используется запасная графика.
Параметры `source`, `anchor` и `scale` управляют только изображением и областью выбора.

Стадия может содержать `layers` (до 32): слои рисуются поверх основы в порядке массива.
У слоя обязательны `image`, `frames` (1–128 прямоугольников `[x,y,w,h]` в PNG) и
`destination` (`[x,y,w,h]` относительно обрезанной основы, в исходных пикселях).
Необязательны `teamMask` (PNG того же размера, что `image`, либо `null`),
`ticksPerFrame` (1–3600, по умолчанию 3), `phase` (начальный индекс кадра, по умолчанию 0)
и `when`: `always` (по умолчанию) или `training`. Последнее требует завершённого здания
и первого заказа с `remainingTicks > 0`; готовый юнит, ожидающий свободного выхода,
уже не считается обучением. Анимация использует тики симуляции и останавливается на
паузе. Один кадр означает статичный слой. Границы кадров и размеры масок проверяются
при проверке ассетов. Слои не меняют логический след здания и область выбора основы.

Основа стадии и каждый слой поддерживают необязательные `emissionMask` (PNG размером
с `image`, либо `null`) и `emissive` (boolean, по умолчанию false). Белый с прозрачностью
задаёт силу сохранения исходной яркости ночью; `emissive: true` включает это для всего
слоя и несовместим с непустой `emissionMask`. Тимколор остаётся отдельной маской.

Готовая стадия может содержать `lights` (до 16). Обязательные поля источника:
`position` (2 координаты относительно `source`, от -8192 до 8192), `radius` (0.1–16 клеток),
`intensity` (0–1) и `color` (3 целочисленные компоненты RGB, 0–255). Необязательные:
`flicker` (0–0.25, по умолчанию 0.04), `when` (`always`/`training`, по умолчанию `always`).
Необязательный `animationLayer` — индекс существующего слоя с `emissive: true` и
совпадающим `when`. Его кадр и `phase` определяют мерцание; без ссылки используется
плавное мерцание от тиков симуляции.
Свет — только отрисовка: не влияет на `dayVision`, `nightVision` или логический туман.
Пример и настройка — [освещение зданий](ASSETS.md#мягкий-свет-здания-ночью).

Размер сетки здания задаётся в `construction.footprint`: `[ширина, высота]`, каждая
сторона от 1 до 8 клеток. Например, у ратуши `[3, 2]`, у более крупного здания можно
указать `[4, 3]`. Размещение, коллизия, подход рабочих, выход юнитов и точка привязки
рисунка используют эти размеры. `anchor` спрайта совмещается с центром прямоугольника
занимаемых клеток; PNG сохраняет свои пропорции, его размер регулируется `scale`.
Размеры и графику нового здания можно задать в каталоге без изменения C++.

`mobility.collisionRadius` — обязательный физический радиус в логических единицах карты,
от 0.05 до 0.5 включительно. Круг не зависит от масштаба спрайта и кольца выделения.
Рабочий, лучник и летун: 0.35; Миротворец: 0.4; герой: 0.45; катапульта: 0.5.
Предел 0.5 сохраняет плотные соседние места строя и проходы шириной в одну клетку;
радиусы больше половины клетки потребуют отдельной поддержки габаритов в навигации и строе.
Для неподвижного здания это поле не используется: его коллизия определяется `construction.footprint`.

30 тиков = 1 секунда. Типы движения: `walking`, `swimming`, `amphibious`, `flying`.
Герой имеет все обычные характеристики, начинает с уровня 1. У остальных `stats.level`
не меняется в матче и используется при начислении опыта за убийство. Урон 0 отключает бой.

Признаки движения и строительства независимы: у будущего живого здания оба могут быть `true`.
Для укоренённой и подвижной формы можно создать два определения и связать их через `alternateForms`.
Сейчас загрузчик проверяет эти связи, но команда превращения ещё не реализована. При её реализации
экземпляр должен сохранять EntityId, владельца, здоровье и прогресс согласно правилам превращения.
Текущая навигация подвижных экземпляров поддерживает след 1×1; движение больших зданий,
взлёт и посадку нужно будет добавить отдельно. Указание `flying` в данных само по себе не поднимает постройку.

Строительство и обучение используют одну цену. Лимит резервируется сразу и возвращается
при отмене; обучение не списывает его повторно при выпуске. Стартовые сущности карты занимают
лимит, но не покупаются за стартовые кристаллы. Подсказки показывают стоимость в кристаллах
и лимите армии, выделяя нехватку цветом. Текущий запас и занятый лимит отображаются в верхней панели.

`stats.mana` — необязательный целый максимум маны от 0 до 1 000 000 (по умолчанию 0).
Юнит появляется с полным запасом. При максимуме 0 интерфейс скрывает ману.
Сейчас у героя 200 маны; регенерация и прирост маны от уровня пока не введены.

`catalog.json` ссылается на отдельную таблицу через `abilitiesFile`.
Необязательный массив `abilities` у юнита содержит до трёх уникальных числовых ID;
он задаёт порядок кнопок Q/W/E в третьем ряду панели команд. Неизвестные ID отвергаются.
В `abilities.json` у записи поля `id`, `name`, `description`, `targeting`, `manaCost`, `cooldownTicks`.
Пока реализован только `targeting: "none"`: мгновенное применение без цели и эффекта.
«Пустышка» имеет ID **1**, стоимость **25 маны** и откат **150 тиков / 5 секунд**.
Текущая мана и остаток отката принадлежат экземпляру юнита, а не каталогу;
откат уменьшается только с тиками симуляции и останавливается на паузе.

## Опыт — общие правила

```json
{
  "version": 1,
  "hero": {
    "experienceRadius": 8,
    "experiencePerVictimLevel": 50,
    "thresholds": [0, 100, 250, 450, 700, 1000, 1400, 1900, 2500, 3200]
  }
}
```

Пороги **накопительные**: уровень 2 требует всего 100 опыта, уровень 3 — всего 250,
то есть ещё 150 после второго. Для следующих переходов нужно 200, 250, 300, 400, 500,
600 и 700 опыта. Десять записей задают максимум 10 уровней. Первый порог — 0,
остальные строго возрастают. При правке сохраняйте увеличение разницы между соседними
порогами, если каждый следующий переход должен быть дороже предыдущего.

Награда равна `experiencePerVictimLevel × уровень жертвы`, делится между живыми героями
армии убийцы в указанном радиусе. Герои максимального уровня и погибшие в том же тике
не участвуют. Общие правила не дублируются в каждой записи героя; индивидуальные приросты
здоровья и урона остаются характеристиками героя. Опыт конкретного героя относится к матчу.

## Расширение каталога и загрузка

1. Добавьте расу в `factions` манифеста: `id`, `name`, `description`.
2. Создайте файл сущностей с той же структурой и внесите его относительный путь в `entityFiles`.
3. Добавьте командиров со ссылками на определения. `startingHero: ""` означает отсутствие героя.
4. Перезапустите игру и проверьте данные командой `& ".\Visages of War.exe" --verify-assets`.

Имена файлов служат организации контента. Можно разделять по расам, командирам или небольшим
пакетам, не создавая отдельного формата или загрузчика для каждой расы. Порядок полей JSON
неважен. Пока порядок определений построек задаёт порядок трёх кнопок строительства.
Стартовый сценарий использует первую доступную постройку своей расы с `depot: true`.
Её след берётся из `construction.footprint`, как у обычной стройки; у текущей ратуши он 3×2.
Карта хранит позицию стартовой базы. Её размеры и занятость клеток вычисляются из каталога
при загрузке и не дублируются в `.rtsmap`. Forge показывает базу первого командира каталога;
матч использует выбранного командира и заново проверяет площадку под его базу.

Сейчас при запуске загружаются **все файлы из манифеста**, один раз. Записи преобразуются
в C++-структуры, каталог индексируется по ID; JSON не участвует в каждом кадре/тике.
Выборочная загрузка пакетов миссии ещё не реализована. Когда объём контента вырастет,
список зависимостей миссии позволит выбирать пакеты без изменения структуры сущности.
Дробить записи по одному файлу для ускорения не требуется: множество мелких файлов тоже
имеет стоимость ввода-вывода. Нужны измерения на реальном объёме данных.

Ссылки каталога на JSON относительны `assets/data`; пути изображений и командных масок — `assets`.
Абсолютные пути и выход через `..` запрещены.
Используются Unicode-пути, рабочая папка процесса значения не имеет. Дубликаты ID и JSON-ключей,
неизвестные/пропущенные поля, неподходящие типы, отрицательные цены и несуществующие ссылки
останавливают загрузку с ошибкой. Добавление нового игрового поля требует изменения общей схемы
загрузчика и всех записей; версия формата сейчас 1. Старые отдельные `.rtsdata` каталоги не читаются.

Для вики достаточно прочитать манифест и собрать `entities` из перечисленных файлов.
У записей уже есть стабильный ID, раса, имя, описание, стоимость, характеристики и связи;
SQL-сервер и копия баланса для вики не нужны. Генератор вики пока не реализован.
